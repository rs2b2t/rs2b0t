## Flags — decide these before Phase 3

**`docs/SCRIPTS.md` is generated.** Header says `GENERATED by tools/gen-scriptdocs.ts — do not edit`, and `test/docs/scriptdocs.test.ts` gates drift. Conforming it means changing the **generator**, not the file. Out of scope for a per-file rewrite pass.

**Root and package READMEs.** `README.md`, `desktop/README.md` and `docs/nav/README.md` are entry points that conventionally mix a little of each type, and `test/docs/links.test.ts` asserts the first two exist by exact path. Treating them as strict single-type docs would either break the test or produce a front page that cannot orient a reader. Recommend exempting them from the one-type rule while still applying the line rules: headings name their content, banned words are deleted, and derivable content stays out.

`docs/script-template/README.md` was on that list while it lived at `templates/`, outside the manual. Under `docs/` it is a manual page like any other, so it is now a single-type how-to and carries no reference tables.

**Splitting breaks the links test.** `test/docs/links.test.ts` asserts every page under `docs/` is reachable from `docs/README.md`. Every new `docs/reference/`, `docs/how-to/` and `docs/decisions/` page must be added to that index in the same commit, and the glob is `docs/*.md` — it does not currently scan subdirectories, so the test needs updating before the first split lands.

## Ambiguous — not guessing

- Whether `docs/nav/` survives as a directory or its pages move into `docs/reference/` and `docs/how-to/`. Both are defensible; the rule does not say.
- Whether "maintainer / private infrastructure" content in `DEV.md` belongs in the public manual at all.
